# SolidBrew PDM — пилот

Первый сценарий: принять рабочий снимок изделия **АИРТ.467124.016 — Имитатор центрального пульта** и выгрузить любую сохранённую версию в новую локальную папку. Входные файлы — головная сборка и чертёж SOLIDWORKS; исходная папка используется только для чтения. Снимок — это копия переданного каталога, а не утверждённая КД и не доказательство, что CAD-ссылки замкнуты. [Границы и приёмка](docs/pilot.md).

[Целевая модель SolidBrew PDM](docs/pdm-concept.md) описывает общее хранилище для SOLIDWORKS, КОМПАС-3D и KiCad: версии документов и зависимостей, блокировки, локальный кэш и адаптеры CAD. [ТЗ](docs/pdm-spec.md) задаёт этапы и критерии приёмки, [архитектура](docs/architecture.md) — стек и устройство компонентов. Эти документы не являются перечнем возможностей текущего стенда.

## Что в репозитории

- `src/SolidBrew.Api/` — ASP.NET Core: карточки изделий, версии рабочих снимков, опись с SHA-256 файлов, выдача архива.
- `compose.yaml`, `infra/minio/` — PostgreSQL и MinIO в закрытой сети Compose. У MinIO и БД нет опубликованных портов; API использует отдельную учётную запись хранилища без права удаления.
- `tools/Inspect-SolidWorks.ps1` — диагностика сохранённых ссылок через запущенный SOLIDWORKS, без открытия исходных документов.
- `tools/pdm.py` — упаковка, импорт, история и проверяемое восстановление локальной копии.

## Запуск (Windows, PowerShell)

Требуются Docker с командой `docker compose` и Linux-контейнерами, а для клиентских инструментов — Python 3.11+ и Windows PowerShell 5.1. Compose собирает MinIO и `mc` из зафиксированных коммитов официальных репозиториев (AGPLv3); первая сборка требует доступа к GitHub и репозиториям зависимостей Go. SOLIDWORKS не запаковывается в Docker; он нужен на рабочем месте для проверки ссылок и открытия моделей.

```powershell
.\tools\New-LocalEnv.ps1
docker compose up -d --build
Invoke-RestMethod http://127.0.0.1:8088/healthz
```

Скрипт генерации `.env` выполняется один раз и не перезаписывает секреты. `/healthz` проверяет соединение с PostgreSQL; доступность MinIO проверяется реальной загрузкой и выдачей. Храните `.env` и каталоги `artifacts/`, `workspaces/` в закрытом месте: последние могут содержать исходную КД. `docker compose down` не удаляет тома; `docker compose down -v` уничтожает лабораторные данные. Для переноса и восстановления нужно сохранять согласованную копию обоих томов.

## Воспроизвести импорт

Укажите исходную папку и точные имена головных файлов. Для одного и того же обозначения карточка создаётся только один раз.

```powershell
$source = 'S:\ИЦ\КО\Перекидки\Войлоков\Для Рустема'
$stem = 'АИРТ.467124.016 Имитатор центрального пульта'
$assembly = $stem + '.SLDASM'
$drawing = $stem + '.SLDDRW'
.\tools\Inspect-SolidWorks.ps1 -Source $source -EntryFiles $assembly,$drawing
if (-not (Test-Path artifacts/pilot-source.zip)) {
    python tools/pdm.py capture --source $source --assembly $assembly --drawing $drawing --output artifacts/pilot-source.zip
}
$item = python tools/pdm.py new-item 'АИРТ.467124.016' 'Имитатор центрального пульта' --kind assembly | ConvertFrom-Json
python tools/pdm.py upload $item.id artifacts/pilot-source.zip --assembly $assembly --drawing $drawing
python tools/pdm.py history $item.id
python tools/pdm.py restore $item.id 1 workspaces/pilot-v1
```

Скрипт восстановления проверяет хеш архива и каждого файла. Импорт не дописывает отсутствующие ссылки, не переименовывает CAD-файлы и не превращает опись в спецификацию. Не открывайте тестовую копию вместе с одноимёнными исходными моделями: так проверка ссылок будет недостоверной.

## Ограничения пилота

- Локальный HTTP и один операторский токен. Это не многопользовательский выпуск: роли, аудит, check-out, надстройка SOLIDWORKS, KiCad и утверждение КД ещё не реализованы.
- 256 МиБ на ZIP, 512 МиБ суммарно по распакованным файлам, 10 000 файлов в снимке. Архив целиком сохраняется в MinIO по отдельному ключу, без дедупликации.
- При сбое между сохранением в MinIO и записью в PostgreSQL в хранилище может остаться невидимый из API объект; версия пользователю не публикуется.
