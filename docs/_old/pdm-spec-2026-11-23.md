# ТЗ на SolidBrew PDM — рабочий черновик

## Назначение

Единое хранилище конструкторских документов для опытного производства полного цикла. Конструктор работает с CAD-документами: не заводит вручную отдельную карточку изделия и не дублирует дерево сборки.

## Первый этап — SOLIDWORKS 2018

1. Поддержать два сценария: разработка с нуля в локальной папке и постановка на учёт готовой сборки из сетевой папки без изменения исходников.
2. Принимать модель без чертежа. Чертёж можно сдать вместе с моделью или позже; у него своя история версий и ссылки на конкретные версии моделей. При изменении только чертежа новую версию модели не создавать.
3. Читать состав из сборки. Карточка PDM и штатное окно CAD работают со свойствами одного документа с учётом конфигурации.
4. Открывать выбранную версию с сервера через локальный кэш. Восстанавливать именно те версии компонентов, с которыми сдана сборка.
5. Разделять локальное сохранение и публикацию. Команда «Сдать сборку» публикует новые и изменённые документы комплекта одной операцией; при ошибке частичный комплект не публикуется.
6. Учтённый документ (деталь, сборка или чертёж) по умолчанию открывается для просмотра без блокировки. Пока сервер не подтвердил взятие в работу, надстройка не разрешает изменять документ ни из карточки PDM, ни штатными командами SOLIDWORKS, в том числе при редактировании детали внутри сборки. По команде «Редактировать» сервер атомарно резервирует только выбранный документ целиком, включая все его конфигурации. Если документ уже занят другим конструктором, надстройка до начала правки показывает, кто его взял, и оставляет документ в режиме просмотра. При одновременных запросах право записи получает только один конструктор. Без подтверждения сервера надстройка не переводит документ в режим редактирования.

   Блокировку меняют явные команды: «Взять в работу» резервирует документ; «Сдать» публикует изменения и только после успешной сдачи освобождает сданный документ; «Отменить взятие в работу» освобождает его без публикации. Если при отмене есть локальные правки, надстройка предупреждает об этом до подтверждения и не удаляет их молча. Локальное сохранение, закрытие SOLIDWORKS и обрыв связи блокировку не снимают. При неудачной сдаче блокировка сохраняется.

   Если локальные изменения всё же появились без действующей блокировки (например, файл изменён вне надстройки), PDM предупреждает о конфликте и не затирает локальные правки. При сдаче сервер проверяет владельца блокировки и исходную версию; при конфликте отклоняет сдачу без изменения опубликованной истории. Новый локальный документ до первой сдачи можно редактировать без блокировки. Опубликованные версии не перезаписываются. Прямой доступ пользователей на запись в архив и БД не предоставляется.

7. Конструктор может отправить на нормоконтроль отдельный документ или комплект по сборке. Для комплекта достаточно выбрать версию головной сборки. PDM сама обходит зафиксированные версии деталей и подсборок и по CAD-ссылкам находит в хранилище чертежи, соответствующие этим версиям моделей. Найденные чертежи по умолчанию включены; конструктор видит список и может исключить лишние перед отправкой. Вручную строить дерево или отмечать каждый документ не требуется. Если связь неоднозначна, PDM показывает это и не выбирает чертёж по одному лишь имени файла. При отправке PDM фиксирует, какие версии переданы. Нормоконтролёр открывает именно их и принимает одно из двух решений: «Принято» или «На доработку». При возврате он указывает замечания текстом. После исправлений конструктор сдаёт новые версии изменённых документов и повторно отправляет документ или комплект на проверку. Предыдущее решение не переносится на новые версии.

Сдача рабочей версии не означает прохождения нормоконтроля. Архивная регистрация и выдача в производство не входят в критерии готовности первого этапа.

## Рабочая папка и поиск чертежей

Для нового проекта PDM создаёт одну локальную рабочую папку. По умолчанию головная сборка, новые детали и подсборки сохраняются в ней, а чертежи — в подпапке `Чертежи/`. Дополнительные подпапки допустимы: структура каталогов не определяет состав изделия. При сдаче PDM ищет чертежи по всей рабочей папке, включая подпапки, и сопоставляет их по ссылкам на модели, а не по именам или месту хранения.

Для импорта старого проекта не требуется предварительная перекладка файлов. Конструктор указывает головную сборку и, если нужно, дополнительные папки для поиска чертежей вне корня проекта. Импорт читает исходники без переноса и переименования; неоднозначные и неразрешённые ссылки показывает отдельно. Весь сетевой диск автоматически не сканируется.

## Целевой охват

- Участники: 10–20 конструкторов, один нормоконтролёр, один архивариус, закупки и производство. Внешний контур — обмен документацией с субподрядчиками по отдельным изделиям; прямой доступ им пока не предполагается как требование.
- Первый CAD-клиент — SOLIDWORKS. Предусмотреть последующее подключение КОМПАС и KiCad. Головная сборка изделия в дальнейшем может быть документом КОМПАС: в общей модели хранилища не отождествлять головную сборку с расширением `.SLDASM`.

## Пока не определено

Правила учёта крепежа и библиотечных компонентов отложены.
