# ТЗ на SolidBrew PDM — рабочий черновик, редакция 2

Предыдущая редакция: [_old/pdm-spec-2026-11-23.md](_old/pdm-spec-2026-11-23.md).

## 1. Назначение и принципы

SolidBrew PDM — простое общее хранилище конструкторских документов SOLIDWORKS, КОМПАС-3D и KiCad для группы конструкторов опытного производства.

Принципы:

1. **Состав берётся из CAD.** Конструктор не заводит вручную карточку изделия и не дублирует дерево сборки. Состав, свойства и связи PDM читает из самих файлов.
2. **Ядро не зависит от CAD.** Документ, версия, зависимость и блокировка описаны общими понятиями. Особенности SOLIDWORKS, КОМПАС и KiCad сосредоточены в адаптерах (раздел 5). Подключение нового CAD не меняет модель данных.
3. **Минимум встраивания в CAD.** На первых этапах PDM работает через отдельный клиент. Надстройки внутри CAD — удобство следующих этапов, а не условие работы.
4. **История неизменна.** Опубликованная версия никогда не перезаписывается. Исправление — только новая сдача.

## 2. Термины

| Термин | Значение |
|---|---|
| Документ | Учтённый в PDM файл (деталь, сборка, чертёж, спецификация) или проект KiCad как единое целое. Имеет внутренний ID, не зависящий от имени файла и обозначения. |
| Версия | Неизменяемое состояние документа, появившееся при сдаче: v1, v2… |
| Зависимость | Ссылка версии документа на конкретную версию другого документа (сборка → деталь, чертёж → модель, сборка → STEP платы). |
| Комплект | Головной документ выбранной версии вместе со всеми зависимостями, зафиксированными при его сдаче. |
| Рабочая папка | Локальная папка конструктора, где лежат файлы для работы в CAD. |
| Кэш | Локальное неизменяемое хранилище скачанных версий на компьютере конструктора. |
| Взять в работу | Получить от сервера блокировку документа на изменение. |
| Сдать | Опубликовать новые версии изменённых и новых документов одной операцией. |
| Отменить взятие | Снять свою блокировку без публикации. |

Эти названия команд используются везде: в клиенте, в документации и в сообщениях.

## 3. Пользователи и роли

- **Конструктор** — 10–20 человек. Ставит на учёт, открывает, берёт в работу, сдаёт.
- **Администратор** — управляет пользователями и библиотекой стандартных компонентов, принудительно снимает чужие блокировки, отвечает за резервное копирование.
- **Читатель** (производство, закупки) — просматривает и выгружает комплекты, ничего не меняет.

Вход — по учётной записи пользователя; каждое действие в журнале связано с конкретным человеком. Способ аутентификации (доменная учётная запись или собственная) — открытый вопрос (раздел 12). Пользователи не получают прямого доступа на запись к архиву и БД — только через API сервера.

Согласующие (проверяющий, технолог, нормоконтролёр, утверждающий), архивариус и внешние субподрядчики — роли следующих этапов (раздел 10).

## 4. Модель данных

Сервер хранит:

- **документы**: ID, тип CAD, текущее имя файла, статус блокировки;
- **версии**: номер, автор, время сдачи, хеш содержимого, исходный относительный путь, версия CAD, в которой файл сохранён, свойства, прочитанные при сдаче (обозначение, наименование, материал и т. п.);
- **зависимости** между версиями;
- **производные файлы** версии (PDF, STEP, DXF, Gerber, BOM), если они сданы вместе с ней или сформированы позже;
- **журнал действий**: кто, что и когда взял, сдал, отменил, переименовал, удалил, выгрузил.

Свойства документа хранятся в БД только как прочитанная при сдаче копия для поиска и просмотра. Источник истины — сам CAD-файл; редактировать свойства в PDM нельзя.

Содержимое файлов хранится в закрытом архиве на сервере отдельно от БД. Способ организации архива — решение архитектуры, а не ТЗ.

## 5. Поддерживаемые CAD

### 5.1. Общие требования к адаптеру

Адаптер CAD умеет для своего формата:

1. определить, какие файлы являются документами;
2. прочитать ссылки документа на другие файлы;
3. прочитать свойства (с учётом конфигураций или исполнений, если они есть);
4. определить версию CAD, в которой сохранён файл.

Адаптер запускается на компьютере конструктора при постановке на учёт и при сдаче. Если для чтения ссылок нужен установленный CAD, это допускается.

### 5.2. SOLIDWORKS

- Документы: `.SLDPRT`, `.SLDASM`, `.SLDDRW`.
- Ссылки и свойства — через API SOLIDWORKS или Document Manager API, с учётом конфигураций.
- Блокировка ставится на файл целиком, со всеми конфигурациями.

### 5.3. КОМПАС-3D

- Документы: `.m3d` (деталь), `.a3d` (сборка), `.cdw` (чертёж), `.spw` (спецификация), `.frw` (фрагмент).
- Ссылки и свойства — через API КОМПАС, с учётом исполнений.
- Спецификация `.spw` учитывается как отдельный документ со ссылками на сборку и её компоненты.

### 5.4. KiCad

- Документ — **проект KiCad целиком**: `.kicad_pro`, схемы `.kicad_sch`, плата `.kicad_pcb` и файлы проекта. Блокируется и версионируется проект, а не отдельные файлы.
- Библиотеки символов и посадочных мест хранятся в проекте (`sym-lib-table`, `fp-lib-table` проекта). Общие библиотеки учитываются как отдельные документы библиотеки (раздел 8).
- 3D-модели компонентов указываются путями относительно проекта (`${KIPRJMOD}`) либо берутся из учтённой библиотеки. Абсолютные пути к личным папкам при сдаче выдаются как ошибка.
- Ссылки читаются разбором текстовых файлов KiCad, запуск KiCad не нужен.
- Выходные файлы (Gerber, сверловка, BOM, PDF схемы, STEP платы) сдаются как производные файлы версии проекта.

### 5.5. Связи между CAD

Документы разных CAD связываются только через файлы обмена, обычно STEP:

- STEP платы из KiCad, вставленный в сборку SOLIDWORKS или КОМПАС, учитывается как документ. PDM хранит, из какой версии проекта KiCad он получен.
- Деталь КОМПАС в сборке SOLIDWORKS (и наоборот) — тоже через STEP с такой же связью.

При сдаче новой версии исходного документа PDM показывает, что связанный STEP устарел. Автоматически он не пересоздаётся.

### 5.6. Версии CAD

- Для каждого CAD в настройках сервера задаётся рабочая версия, например SOLIDWORKS 2018. Файлы SOLIDWORKS и КОМПАС не открываются в более старых версиях программы.
- При сдаче PDM записывает версию CAD, в которой сохранён файл. Файл, сохранённый в версии новее рабочей, сдаётся только после предупреждения.
- При открытии клиент предупреждает, если в комплекте есть файлы новее установленной версии CAD.

Головная сборка изделия может быть документом любого из поддерживаемых CAD.

## 6. Рабочее место

На компьютере конструктора работает **клиент PDM** — настольное приложение Windows. Оно держит кэш и рабочие папки. Для тех же операций есть командная строка; она нужна для автоматизации и диагностики, а не для повседневной работы.

- Каждый проект или изделие разворачивается в свою рабочую папку. Структура подпапок свободная и не определяет состав изделия. По умолчанию чертежи кладутся в подпапку `Чертежи/`.
- Файлы, не взятые в работу, лежат в рабочей папке **только для чтения** (атрибут файловой системы). Так защищаются от случайной правки все три CAD без надстроек.
- «Взять в работу» снимает атрибут только после подтверждения блокировки сервером.
- Правка в рабочей папке не повреждает кэш. Повторное открытие версии не затирает несданные локальные правки: клиент предупреждает и спрашивает.
- CAD работает только с локальными файлами, не по сети.

### 6.1. Интерфейс пользователя

Графический интерфейс обязателен с первого этапа. Все операции раздела 7 выполняются из него без командной строки.

Веб-интерфейс на первом этапе не делается: клиент должен работать с локальными файлами, кэшем и COM API CAD, а браузер этого не умеет. Читатели пользуются тем же приложением в режиме только для чтения.

Интерфейс построен вокруг **окна изделия** (подробно — [ui-redesign.md](ui-redesign.md)): одно окно — одно изделие и его рабочая папка. Изделием может быть любая сборка; тренажёр, кокпит, мостик — равноправные документы, разница только в том, с какого корня смотреть.

1. **Вход** под учётной записью пользователя.
2. **Стартовое окно**: закреплённые и недавние изделия, корневые изделия (сборки, не входящие в другие), поиск по всем сборкам, «Поставить на учёт новое изделие».
3. **Окно изделия**:
   - шапка: переключатель изделия (в этом окне или в новом), рабочая папка, «Сдать (N)», меню (выгрузка, постановка на учёт, администрирование, настройки);
   - слева — **дерево изделия** по ссылкам CAD, чертежи под тем, что они изображают; фильтр по обозначению, наименованию, имени файла и быстрые отборы (взятые мной, изменённые, устаревшие, с проблемами); узел «Новые файлы» для черновиков. Состояния: свободен, взят мной, взят другим (кем), изменён локально, черновой, устарел, нет файла, устаревший STEP (этап 2);
   - справа — **панель узла**: шапка, только применимые к узлу команды («Открыть в CAD», «Взять в работу», «Сдать», «Отменить взятие», «Обновить до последней», в меню — «Переименовать», «Где применяется», «Не используется») и вкладки по типу узла: «Карточка» (свойства CAD по конфигурациям, только чтение), «Состав» (сборка), «Модель» (чертёж), «Версии», «Где применяется», «Журнал». Вкладки подключаемые: нормоконтроль, PDF, спецификация, позиционные обозначения добавляются следующими этапами как новые вкладки.
4. **Сдача**: список новых и изменённых документов с отметками, найденные проблемы (нет зависимости, устарела исходная версия, файл сохранён в более новой версии CAD, абсолютный путь в KiCad), поле комментария. Сдача невозможна, пока есть блокирующие ошибки.
5. **Постановка на учёт**: выбор головного документа и папок поиска, отчёт по ссылкам — найденные, отсутствующие, за пределами папок, совпавшие только по имени, — и подтверждение.
6. **Конфликты при открытии** — только если в рабочей папке есть локальные правки или чужие файлы на тех же путях.
7. **Выгрузка комплекта** с выбором состава: исходные файлы, производные файлы.
8. **Администрирование** (только для администратора): пользователи и роли, текущие блокировки с принудительным снятием, библиотека, рабочие версии CAD.

Длительные операции (скачивание, чтение ссылок, сдача) показывают ход выполнения и не блокируют окно. Ошибки описываются понятным языком с указанием документа и того, что сделать.

## 7. Операции первого этапа

### 7.1. Поставить на учёт

**Новый проект.** Конструктор создаёт документы в рабочей папке. До первой сдачи они черновые, видны только ему и редактируются без блокировки. Первая сдача присваивает им ID и v1.

**Готовый проект с сетевого диска.** Конструктор указывает головной документ и, при необходимости, дополнительные папки для поиска чертежей и спецификаций. PDM:

1. читает исходники, не перемещая, не переименовывая и не изменяя их;
2. строит дерево по ссылкам;
3. отдельно показывает отсутствующие файлы, ссылки за пределами указанных папок и совпадения только по имени файла;
4. показывает для каждого документа, что с ним будет, и даёт снять галочку «загружать» у любого документа, кроме головного:
   - файл, содержимое которого (SHA-256) уже есть в PDM, не заводится заново — ссылка привязывается к этой версии, при открытии файл берётся из хранилища;
   - файл без галочки в PDM не загружается: ссылка на него остаётся путём, и CAD при открытии берёт его по этому пути. Это осознанное решение, а не отсутствующая ссылка;
5. ставит комплект на учёт одной операцией после подтверждения конструктора.

Весь сетевой диск автоматически не сканируется. Чертежи сопоставляются с моделями по ссылкам, а не по именам или месту хранения. При неоднозначности PDM показывает её и не выбирает файл по одному имени.

### 7.2. Открыть версию

Конструктор выбирает документ и версию (по умолчанию последнюю). Сервер отдаёт список точных версий комплекта, клиент докачивает недостающее в кэш, раскладывает файлы в рабочую папку с исходными именами и относительными путями и открывает головной документ в нужном CAD.

Открывается именно тот комплект, который был сдан: сборка v7 с деталью v3, даже если уже есть v4. Повторное открытие берёт файлы из кэша.

Если в рабочей папке уже лежит другая версия того же файла, клиент сообщает об этом, а не подменяет файл молча.

### 7.3. Взять в работу

- Сервер атомарно резервирует выбранный документ. При одновременных запросах блокировку получает только один конструктор.
- Если документ занят, клиент показывает, кем и с какого времени, и оставляет файл только для чтения.
- Для изменения состава сборки берётся в работу сама сборка. Для правки детали — деталь. Двое могут одновременно менять разные детали одной сборки.
- Закрытие CAD, выключение компьютера и обрыв связи блокировку не снимают.

### 7.4. Сдать

- Клиент находит в рабочей папке изменённые взятые документы и новые черновые документы, показывает список, конструктор подтверждает.
- Адаптер читает ссылки и свойства. Сервер проверяет: блокировки принадлежат сдающему, исходные версии не устарели, все обязательные зависимости есть либо в хранилище, либо в этой же сдаче.
- Публикация атомарна: либо все документы получают новые версии, либо ни один. При ошибке блокировки и локальные правки сохраняются, история не меняется.
- После успешной сдачи блокировки снимаются. Вариант **«Сдать и оставить в работе»** публикует версии и сохраняет блокировки.
- Изменение только чертежа не создаёт новую версию модели. Изменение модели не создаёт новую версию чертежа автоматически.
- Конструктор может указать комментарий к сдаче.

### 7.5. Отменить взятие

Снимает блокировку без публикации. Если есть локальные правки, клиент предупреждает до подтверждения и не удаляет их молча.

### 7.6. Обновить зависимость

Новая версия детали не меняет существующие версии сборок. Чтобы сборка использовала новую версию детали, конструктор берёт сборку в работу, открывает её с новой версией детали и сдаёт сборку. Новая привязка фиксируется новой версией сборки, даже если байты файла сборки не изменились.

### 7.7. Где применяется

Для любой версии документа PDM показывает, в какие версии сборок, чертежей и спецификаций она входит, и отдельно отмечает, где используется не последняя версия.

### 7.8. Поиск и просмотр

- Поиск по обозначению, наименованию, имени файла и автору.
- Для документа видны история версий с авторами, датами и комментариями, текущая блокировка, свойства версии, зависимости и производные файлы.

### 7.9. Переименование, перемещение, удаление

- Переименование и перемещение выполняются только через клиент PDM. Клиент берёт в работу последние версии документов, которые ссылаются на переименованный, обновляет в них ссылки и сдаёт всё одной операцией. Если какой-то из них занят другим конструктором, операция не выполняется. Старые версии сборок продолжают открываться со старым именем файла.
- Удаление документа, на который ссылаются опубликованные версии, запрещено. Документ можно пометить как «не используется»: он пропадает из поиска по умолчанию, история сохраняется.

### 7.10. Выгрузить комплект

Любой пользователь может выгрузить выбранную версию комплекта в ZIP: исходные файлы с относительными путями и производные файлы (PDF, STEP, Gerber). В архив кладётся перечень файлов с версиями и хешами. Выгрузка фиксируется в журнале.

### 7.11. Снять чужую блокировку

Администратор может принудительно снять блокировку, например если конструктор в отпуске. Владелец блокировки при следующем подключении получает уведомление; его локальные правки не удаляются. Действие фиксируется в журнале.

## 8. Библиотечные компоненты

- Стандартные изделия, крепёж, покупные компоненты и общие библиотеки KiCad хранятся в отдельном разделе **«Библиотека»** как обычные документы с версиями.
- Конструкторы используют библиотеку только для чтения. Изменения вносит администратор или назначенный им ответственный.
- Сборки ссылаются на конкретные версии библиотечных документов, как и на любые другие.
- Детали SOLIDWORKS Toolbox на первом этапе учитываются как обычные файлы-копии в библиотеке. Генерация деталей Toolbox «на лету» при открытии не используется.

Правила учёта крепежа в спецификации по ЕСКД — в разделе 10.

## 9. Нефункциональные требования

- Сервер — одна машина в локальной сети предприятия. Клиент работает под Windows 10 и 11, ставится установщиком без ручной настройки и обновляется с сервера.
- Выбранный стек и устройство компонентов описаны в [architecture.md](architecture.md).
- Типичный комплект — до нескольких сотен файлов и сотен мегабайт. Повторное открытие без изменений не скачивает файлы заново.
- БД и архив резервируются согласованно, ежедневно. Процедура восстановления проверена на отдельной машине.
- Опубликованные версии не может изменить или удалить ни один пользователь, включая администратора PDM через клиент.

## 10. Следующие этапы

Не входят в первый этап и не являются его критериями готовности. Порядок — по важности для опытного производства.

1. **Согласование и нормоконтроль по версиям.** Документ или комплект отправляется на согласование по версии головной сборки; PDM сама собирает чертежи и спецификации по ссылкам. Маршрут — подписи основной надписи по ГОСТ 2.104 (разработал, проверил, т. контр., н. контр., утвердил), набор участников задаётся для вида документа и может быть изменён при отправке. Каждый участник ставит «Принято» или «На доработку» с замечаниями к конкретному документу. Решения и подписи фиксируются в журнале с автором и временем, относятся к конкретным версиям и не переносятся на новые: новая сдача после «На доработку» запускает согласование этой версии заново. Пока комплект на согласовании, его документы можно сдавать, но на согласовании остаются именно отправленные версии.
2. **Спецификация по ЕСКД и выпуск.**
   - Спецификация по ГОСТ 2.106 формируется из зафиксированной версии сборки и выбранной конфигурации, с правилами учёта крепежа, стандартных и покупных изделий. Дерево CAD не равно утверждённой спецификации: сформированная спецификация проверяется конструктором и сдаётся как документ комплекта.
   - Выпуск — утверждённый набор точных версий документов комплекта, прошедший согласование по пункту 1. Выпуску присваиваются литера по ГОСТ 2.103 и номер изменения (для первого выпуска — 0). Выпущенные версии выдаются в производство; внутренние версии, появившиеся после выпуска, в него не попадают. Роль архивариуса — учёт выпусков и выдача.
3. **Извещения об изменении** по ГОСТ 2.503. Выпущенный комплект меняется только через извещение:
   - извещение содержит обозначение, причину и код изменения, указание о заделе и внедрении и перечень изменяемых документов с прежней (выпущенной) и новой версией каждого;
   - новые версии готовятся обычной сдачей и до утверждения извещения остаются внутренними;
   - извещение проходит согласование по пункту 1 вместе с перечисленными версиями;
   - после утверждения изменённые документы получают следующий номер изменения, появляется новый выпуск комплекта; предыдущий выпуск остаётся доступен для открытия и выгрузки;
   - для каждого выпущенного документа видна история изменений: номера изменений, извещения, даты.
4. **Надстройки SOLIDWORKS и КОМПАС**: команды PDM прямо из CAD, карточка документа, совместная с окном свойств CAD.
5. **Веб-портал** для просмотра и выгрузки выпущенных комплектов без установки клиента — для производства и закупок, позже для субподрядчиков. Работает через тот же API сервера, только чтение.
6. **Внешний доступ** для субподрядчиков.

## 11. Порядок внедрения и приёмка

**Этап 1. Ядро и SOLIDWORKS.** Готов, когда на замкнутом комплекте с подсборкой, общей деталью, двумя конфигурациями и чертежами показано:

1. Готовый проект ставится на учёт с сетевой папки без изменения исходников. Отсутствующие и неоднозначные ссылки показаны отдельно.
2. На другом компьютере, без доступа к исходной папке и без ранее открытых одноимённых файлов, открываются старая и новая версии сборки. В SOLIDWORKS проверены реальные пути загруженных компонентов в обеих конфигурациях. Повторное открытие идёт из кэша.
3. Два конструктора независимо сдают изменения разных деталей одной сборки. Попытка одновременно взять один файл отклоняется. Файл, не взятый в работу, нельзя сохранить в CAD.
4. Новая сборка с новыми деталями и чертежами сдаётся целиком. При отсутствующей зависимости или сбое ничего не публикуется частично, локальные правки сохраняются.
5. Новая версия детали не меняет старую сборку. После явного обновления зависимости появляется новая версия сборки. «Где применяется» показывает обе.
6. Изменение только чертежа создаёт новую версию чертежа, но не модели.
7. Переименование детали, используемой в сборке, не ломает открытие сборки.
8. Комплект выгружается в ZIP с перечнем версий и хешей.
9. Сценарии 1–8 выполняются конструктором из графического интерфейса клиента, без командной строки.

Для пилотного комплекта АИРТ.467124.016 сначала нужно получить две отсутствующие детали (см. [pilot.md](pilot.md)) или выбрать другой замкнутый комплект.

**Этап 2. КОМПАС и KiCad.** Готов, когда сценарии 1–9 повторены для сборки КОМПАС со спецификацией и для проекта KiCad, а STEP платы из KiCad учтён в сборке SOLIDWORKS со связью на версию проекта. Модель данных ядра при этом не меняется.

**Этап 3 и далее** — по разделу 10.
