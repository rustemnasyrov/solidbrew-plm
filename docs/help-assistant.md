# Помощник в клиенте: план

Черновик, 24.11.2026. Справка с агентом, который отвечает на вопросы конструктора «что к чему» в контексте того, что сейчас открыто.

## Что хотим

- **Окно помощника всегда на месте.** Одна постоянная панель в одном и том же месте окна изделия (и стартового окна). Она не появляется и не исчезает от действий; её можно только свернуть в узкую полосу у края.
- **Ответ — в контексте.** Помощник знает, какой элемент дерева выбран и какая вкладка панели узла открыта, и отвечает про них: «почему деталь устарела», «кто взял сборку и когда», «что значит эта ошибка сдачи», «как обновить подсборку до новой версии».
- **Агент — ваш.** Клиент подключается к уже работающему агенту: Claude Code, opencode или другому. Сам клиент модель не содержит.
- **На первом этапе помощник только читает и объясняет.** Брать в работу, сдавать, переименовывать он не может.

## Как выглядит

Окно изделия получает третью колонку справа — **«Помощник»**:

```
┌ шапка изделия ─────────────────────────────────────────────────────────┐
│ дерево с фильтром │ панель узла (вкладки)        │ Помощник            │
│                   │                              │ Контекст: ПИ.101 Ось │
│                   │                              │  · вкладка «Версии»  │
│                   │                              │ ─────────────────── │
│                   │                              │ история вопросов     │
│                   │                              │ подсказки вопросов   │
│                   │                              │ [ поле вопроса     ] │
└───────────────────┴──────────────────────────────┴─────────────────────┘
```

- Сверху — **строка контекста**: выбранный узел, его состояние, открытая вкладка. Меняется сама при выборе другого узла; её можно закрепить, чтобы спросить про один узел, глядя на другой.
- **Подсказки вопросов** зависят от контекста: у устаревшей детали — «Почему устарела?», «Что изменилось в новой версии?»; у взятой другим — «Кто и когда взял?»; после ошибки сдачи — «Почему сдача не прошла?».
- Ошибки в окнах клиента получают ссылку «Спросить помощника» — вопрос с текстом ошибки уходит в ту же панель.
- История вопросов — своя у каждого окна изделия, хранится локально.

## Устройство

### 1. Контекст из клиента
Клиент собирает при каждом вопросе блок контекста: изделие и рабочая папка, выбранный узел (документ, версия, последняя версия, состояние, кем взят), открытая вкладка и её главное содержимое (например, список версий), роль пользователя, последние ошибки. Блок прикладывается к вопросу и доступен агенту инструментом `current_context`.

### 2. MCP-сервер SolidBrew (`SolidBrew.Mcp`)
Небольшой процесс на .NET, который запускает агент (stdio). Работает **от имени вошедшего пользователя** — тем же сохранённым входом из профиля клиента, с теми же правами. Инструменты только для чтения:

| Инструмент | Что отдаёт |
|---|---|
| `current_context` | контекст из открытого окна клиента (через локальный канал) |
| `search_documents` | поиск по обозначению, наименованию, файлу, автору |
| `get_document` | карточка: свойства, версии с комментариями, блокировка |
| `get_kit` | состав комплекта версии, с чертежами |
| `where_used` | применения всех версий |
| `get_journal` | журнал документа |
| `workspace_status` | состояние рабочей папки: изменённые, взятые, черновики |
| `explain_problem` | расшифровка кода проблемы (`staleBaseVersion`, `lockedByOther`…) и что делать |

Ресурсы — документация: руководство конструктора, ТЗ, инструкция приёмки, справочник кодов проблем.

Этот же сервер можно подключить к агенту и вне клиента — спрашивать про PDM прямо из Claude Code или opencode.

### 3. Подключение к агенту
Клиент говорит с агентом через интерфейс `IAssistantBackend` с реализациями:

| Агент | Как подключаемся |
|---|---|
| Claude Code | `claude -p` с потоковым JSON-выводом и `--mcp-config` на `SolidBrew.Mcp` |
| opencode | его локальный сервер (HTTP API) с подключённым `SolidBrew.Mcp` |
| OpenAI-совместимый (Ollama, LM Studio и т. п.) | чат с вызовом инструментов; инструменты исполняет сам клиент |

Выбор агента и путь к нему — в «Настройках». Если агент не настроен, панель показывает, как его подключить, и умеет искать по встроенной документации без модели.

### 4. Знания
Чтобы ответы были точными, нужны тексты, которых пока нет:
- **руководство конструктора** (`docs/user-guide.md`): основные операции окна изделия шаг за шагом;
- **справочник кодов проблем**: каждый код сдачи, блокировки и открытия — что значит и что делать.

## Безопасность и данные
- Только чтение: в MCP-сервере нет инструментов изменения.
- Права — пользователя: агент видит то же, что пользователь в клиенте.
- **Куда уходят данные.** Обозначения, наименования, имена файлов и журнал уходят в модель агента. Если агент работает с облачной моделью, эти данные покидают предприятие. Нужно решение (см. ниже); при облачной модели — явное предупреждение в «Настройках».
- Содержимое CAD-файлов агенту не передаётся.

## Этапы
1. **Панель и контекст:** постоянная колонка, строка контекста, подсказки, история; `SolidBrew.Mcp` с инструментами чтения; подключение к одному агенту; руководство конструктора и справочник кодов.
2. **Глубже в контекст:** «Спросить помощника» из ошибок; подсказки для каждой вкладки; второй и третий тип агента.
3. **Действия с подтверждением** (позже, отдельным решением): помощник готовит план («взять в работу эти три документа и обновить подсборку»), пользователь подтверждает кнопкой в клиенте.

## Решения, которые нужны

1. **Какой агент подключаем первым** — Claude Code, opencode или локальная модель через Ollama.
2. **Можно ли отправлять данные PDM в облачную модель.** Если нет — первым делом подключаем локальную модель, облачные — только с разрешения администратора.
3. **Где панель:** предлагаю правую колонку окна изделия, сворачиваемую в полосу.

## Проверка готовности этапа 1
- Выбор узла меняет строку контекста; вопрос «почему устарела?» про устаревшую деталь даёт ответ с номерами версий и автором новой версии.
- Вопрос про ошибку сдачи даёт объяснение кода и шаги исправления.
- Агент не может ничего изменить в PDM (в MCP-сервере нет таких инструментов; проверено тестом).
- Без настроенного агента панель работает как поиск по документации.
