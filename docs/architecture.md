# SolidBrew PDM: архитектура и стек

Документ фиксирует технические решения для [ТЗ](pdm-spec.md) и [целевой модели](pdm-concept.md). Это план, а не описание текущего стенда.

## 1. Общая схема

```
Рабочее место конструктора (Windows)            Сервер (Windows)       
┌────────────────────────────────────┐          ┌──────────────────────────┐
│ Клиент PDM (WPF)    CLI             │  HTTPS   │ API: ASP.NET Core, Docker│
│        └────┬────┘                  │ ───────► │   ├─ PostgreSQL (Docker) │
│   Ядро клиента: API, кэш, папки     │          │   └─ MinIO (служба Win)  │
│   Адаптеры: SW · КОМПАС · KiCad     │          └──────────────────────────┘
│        │ COM            │ файлы     │
│   SOLIDWORKS, КОМПАС   KiCad        │
└────────────────────────────────────┘
```

Клиент — настольное приложение. Веб-интерфейс на первом этапе не делается: клиенту нужны локальные файлы, кэш, атрибуты файлов и COM API CAD, а браузер этого не умеет. Веб-портал для просмотра и выгрузки — следующий этап, на том же API.

## 2. Клиент

| Решение | Выбор | Почему |
|---|---|---|
| Платформа | .NET 10, только Windows | CAD работают только под Windows; совпадает с сервером |
| Интерфейс | WPF | Зрелый, хорошо держит деревья на тысячи узлов. Кроссплатформенность (Avalonia, MAUI) не нужна |
| Шаблон | MVVM, CommunityToolkit.Mvvm | Логика отделена от экранов и тестируется без окон |
| Командная строка | Тот же код ядра, отдельный исполняемый файл | Автоматизация и диагностика; заменяет [tools/pdm.py](../tools/pdm.py) |
| Установка | MSIX или MSI, обновление с сервера | Без ручной настройки на рабочем месте |

Сборки клиента:

| Сборка | Целевая платформа | Содержимое |
|---|---|---|
| `SolidBrew.Core` | `netstandard2.0` | Модель данных, клиент API |
| `SolidBrew.Workspace` | `net10.0-windows` | Кэш, рабочие папки, атрибуты «только для чтения» |
| `SolidBrew.Adapters.SolidWorks` | `net10.0-windows` | Ссылки, свойства, версия файла через COM |
| `SolidBrew.Adapters.Kompas` | `net10.0-windows` | То же через API КОМПАС |
| `SolidBrew.Adapters.KiCad` | `net10.0` | Разбор S-выражений файлов KiCad |
| `SolidBrew.Client` | `net10.0-windows` | WPF-приложение |
| `SolidBrew.Cli` | `net10.0-windows` | Командная строка |

`SolidBrew.Core` собирается под `netstandard2.0`, потому что будущие надстройки SOLIDWORKS 2018 и КОМПАС загружаются внутрь CAD и требуют .NET Framework 4.x. Так модель и клиент API потом переиспользуются без переписывания.

### Адаптеры

**SOLIDWORKS.** Два способа читать ссылки и свойства:

| Способ | Плюсы | Минусы |
|---|---|---|
| Document Manager API | Быстро, SOLIDWORKS не запускается | Нужен лицензионный ключ, его выдают клиентам с подпиской |
| Автоматизация запущенного SOLIDWORKS через COM | Ключ не нужен; так уже работает [Inspect-SolidWorks.ps1](../tools/Inspect-SolidWorks.ps1) | Медленно, нужен установленный SOLIDWORKS |

Адаптер скрывает способ за общим интерфейсом; выбор — по наличию ключа (открытый вопрос ТЗ).

**КОМПАС-3D.** COM API КОМПАС, вызов вне процесса КОМПАС. Нужен установленный КОМПАС.

**KiCad.** Файлы текстовые, адаптер разбирает их сам. KiCad не запускается.

Все адаптеры работают вне процесса CAD. Надстройки, работающие внутри CAD, — следующий этап.

## 3. Сервер

| Решение | Выбор | Почему |
|---|---|---|
| API | ASP.NET Core на .NET 10, как в [SolidBrew.Api](../src/SolidBrew.Api/SolidBrew.Api.csproj) | Уже есть каркас, Docker и проверка архивов |
| БД | PostgreSQL 17 | Транзакции для атомарной сдачи, ограничения для блокировок |
| Доступ к БД | Npgsql + Dapper | Модель небольшая; ближе к текущему коду, чем EF Core |
| Архив | MinIO, установленный нативно как служба Windows (не в Docker); данные — обычная папка на диске (`PDM_ARCHIVE_DIR`). Установка — `tools/Install-MinIO.ps1`: бинарники `minio.exe` и `mc.exe` последнего опубликованного community-релиза с проверкой SHA-256, служба, бакет `pdm-objects`, пользователь `pdm-api` с политикой Get/Put | Содержимое по SHA-256 (ключ `objects/ab/<sha256>`), хранилище скрыто за API. MinIO не требует окружения, Docker-тома не раздуваются. С 2025 года MinIO не выпускает новые community-сборки; для обновления — сборка из зафиксированного коммита (Go, `GOOS=windows`) |
| Аутентификация | Windows-аутентификация (Negotiate) при наличии домена, иначе свои учётные записи с токенами | Открытый вопрос ТЗ |
| Развёртывание | Docker Compose для PostgreSQL и API; MinIO — служба Windows на той же машине | API обращается к MinIO по `PDM_S3_ENDPOINT` (`host.docker.internal:9000`) |

Ключевые механизмы:

- **Блокировка** — строка в таблице блокировок с уникальным ограничением по документу. Два одновременных запроса не могут оба пройти.
- **Сдача** в три шага:
  1. клиент отправляет список хешей, сервер отвечает, каких объектов нет в архиве;
  2. клиент загружает только недостающие объекты, сервер проверяет хеши;
  3. одна транзакция БД проверяет блокировки и исходные версии и публикует версии и зависимости.

  Объекты, загруженные без последующей публикации, со временем удаляет фоновая очистка.
- **Неизменность** — служба работает под отдельной ролью БД; изменение и удаление опубликованных версий запрещено правами и триггерами.

## 4. Что делать с текущим кодом

| Компонент | Решение |
|---|---|
| `SolidBrew.Api` | Каркас и Docker остаются; MinIO выносится из Docker в службу Windows. Модель ZIP-снимков заменяется моделью «документ — версия — зависимость — блокировка» |
| `tools/pdm.py`, `tools/cad_archive.py` | Остаются прототипом, пока нет .NET CLI; затем удаляются, чтобы не вести два клиента |
| `tools/Inspect-SolidWorks.ps1` | Образец для адаптера SOLIDWORKS; после появления адаптера — удалить |
| `tests/` | Python-тесты уходят вместе с `pdm.py`; новые тесты — на .NET (xUnit) |

## 5. Первые проверки до начала разработки интерфейса

Короткий прототип на .NET, который читает ссылки одного замкнутого комплекта и печатает дерево с версиями CAD:

1. **SOLIDWORKS:** interop-сборки 2018 года и файлы пилота, проверенные в 26.1. Определить, в какой версии сохранены файлы и открываются ли они в рабочей версии.
2. **Document Manager API:** есть ли ключ; если нет — проверить скорость чтения через автоматизацию SOLIDWORKS на комплекте из ~150 файлов.
3. **КОМПАС:** чтение ссылок из `.a3d` и `.spw` на рабочей версии КОМПАС.
4. **KiCad:** разбор проекта рабочей версии KiCad, включая таблицы библиотек и пути к 3D-моделям.

Результаты прототипа уточняют этот документ и снимают открытые вопросы ТЗ.

### Где и как проверяется всё, что связано с SOLIDWORKS

SOLIDWORKS установлен не на машине разработки, а на отдельном компьютере с Windows. Папка проекта доступна ему по сети, поэтому собирается всё на машине разработки, а запускается там — из общей папки или её копии.

COM-автоматизация SOLIDWORKS через SSH не работает: у SSH-сессии нет рабочего стола, SOLIDWORKS в ней не запускается или падает. Поэтому:

1. **Первый шаг прототипа** — проверить это на той машине. Проверено 23.11.2026 на SOLIDWORKS 26.1: из SSH-сессии `GetActiveObject('SldWorks.Application')` даёт `MK_E_UNAVAILABLE`. Задача планировщика с `LogonType Interactive`, созданная и запущенная из SSH без пароля, выполняется в сессии вошедшего пользователя, и там объект доступен. Вызовы работают через `IDispatch` (позднее связывание C#); встроенный COM-адаптер PowerShell на объектах SOLIDWORKS падает с `TYPE_E_ELEMENTNOTFOUND`.
2. **Исполнитель заданий `SwProbe serve`.** Небольшая консольная программа, которую пользователь один раз запускает в своей интерактивной сессии (или через `schtasks /IT` от имени вошедшего пользователя). Она забирает задания из общей папки `.swjobs/inbox`, выполняет их через COM запущенного SOLIDWORKS (чтение ссылок и свойств, версии файлов, генерация тестового комплекта, открытие с проверкой путей компонентов) и пишет результат в `.swjobs/outbox`. Так тесты адаптера гоняются с машины разработки без участия человека.
3. **SSH** — для копирования сборок, запуска тестов без SOLIDWORKS и запуска исполнителя через `schtasks /IT`. Вход только по ключу, пароли не передаются.
4. **Document Manager API** снял бы ограничение, но нужен лицензионный ключ (открытый вопрос ТЗ 12.6).
5. **Сценарии с интерфейсом** (WPF-клиент вместе с SOLIDWORKS, запрет сохранения не взятого файла, два конструктора, второй компьютер) проверяет человек у экрана по описанию в `docs/acceptance-stage1.md`.
